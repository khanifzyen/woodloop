## 13. Perbaikan `getFileUrl` — dari SDK ke URL Manual
Kami mengubah implementasi `getFileUrl` karena `pb.files.getURL()` terkadang gagal di runtime.

*   **Sebelumnya:** `pb.files.getURL(record, filename)` — bergantung pada SDK internal state dan `collectionId` dari record.
*   **Sesudahnya:** URL konstruksi manual — `${PB_URL}/api/files/${collectionName}/${recordId}/${filename}` — lebih stabil karena pakai nama koleksi yang sudah pasti.
*   **Update Semua Pemanggil:** 12 file di-update signature dari `(record, filename)` ke `(collectionName, recordId, filename)`.

## 20. Perbaikan Cache Invalidation (Delete Tidak Langsung Hilang)
Kami memperbaiki bug di mana data yang dihapus masih muncul 1-2 menit setelah delete karena React Query cache tidak ter-invalidate.

*   **Akar Masalah:** Query key builder `listings()` tanpa argumen return `["supplier", "listings", undefined]` (3 elemen), tapi halaman inventory menggunakan filter object `["supplier", "listings", { status: "available" }]`. `undefined` vs `{}` mismatch → `invalidateQueries` tidak kena.
*   **Fix — Semua 6 hook files:** Key builder sekarang return 2 elemen (`["supplier", "listings"]`) saat tanpa filter, jadi prefix matching works untuk invalidate apa pun filter-nya.
    *   `use-supplier.ts` — `listings()`, `use-generator.ts` — `wasteListings()`, `timberMarketplace()`.
    *   `use-aggregator.ts` — `pickups()`, `availableWaste()`, `wasteListings()`.
    *   `use-converter.ts` — `marketplace()`, `designRecipes()`.
    *   `use-buyer.ts` — `products()`, `orders()`.
    *   `use-enabler.ts` — `metrics()`, `users()`.
*   **Hasil:** Delete/update/create langsung invalidate cache. UI update instan tanpa delay.
