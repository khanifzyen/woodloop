## Detail Pengujian

### ✅ Login
- Navigasi ke `/login`
- Isi email & password, klik "Masuk"
- Redirect ke `/supplier/dashboard`
- Cookie auth: `pb_auth` (JWT) + `pb_role=supplier`

### ✅ Dashboard (`/supplier/dashboard`)
- **4 SummaryCards:** Listing Aktif, Order Masuk, Total Penjualan, Saldo Dompet
- **Quick Menu:** 3 kartu navigasi (Inventaris Kayu, Pesanan Masuk, Riwayat Penjualan)
- **Aktivitas Terbaru:** Menampilkan "Belum ada aktivitas" (empty state)
- **Sidebar Navigation:** Dashboard, Inventaris Kayu, Pesanan Masuk, Riwayat Penjualan

### ✅ Inventory List (`/supplier/inventory`)
- **Tombol:** "Daftarkan Kayu Baru" (link ke `/inventory/new`)
- **Filter:** Search input, status filter, wood type filter
- **Empty state:** Tabel/list kosong dengan prompt

### ❌ Inventory Create Form (`/supplier/inventory/new`) — **Bug Ditemukan**
- Form menggunakan controlled component React (`useState`)
- **Masalah:** Browser automation (`agent-browser fill`, `keyboard inserttext`) tidak memicu React synthetic `onChange` event
- Nilai terisi di DOM tapi React state kosong → error validasi "Volume harus diisi"
- **Workaround:** Upload file berhasil via `input[type="file"]` langsung
- **CRUD API diverifikasi berfungsi 100%** melalui curl langsung ke PocketBase:
  - ✅ **CREATE** — Listing baru dengan `shape:log`, `volume:2.5`, `price:750000`
  - ✅ **READ** — `getList` mengembalikan 1 listing
  - ✅ **UPDATE** — `PATCH` price menjadi `800000`
  - ✅ **DELETE** — `DELETE` status `204 No Content`
- Akar masalah: React controlled input tidak mendeteksi perubahan dari non-React automation. Bisa diperbaiki dengan `keyboard type` yang memicu keystroke events, atau refactor ke uncontrolled form.

### ✅ Orders (`/supplier/orders`)

### ✅ Sales (`/supplier/sales`)

## Bug & Catatan

1. **React Controlled Form Issue** — Form `inventory/new` menggunakan controlled inputs via `useState`. Saat diisi melalui browser automation (`fill`, `keyboard inserttext`), perubahan nilai DOM tidak memicu React synthetic `onChange`, sehingga state form tetap default dan validasi gagal. **Solusi:** Gunakan `keyboard type` (keystroke events) atau refactor ke uncontrolled form.

2. **Semua halaman supplier bisa diakses dan merender dengan benar.** Tidak ada crash, error 500, atau broken layout.

3. **CRUD API endpoint berfungsi penuh** — CREATE, READ, UPDATE, DELETE semua sukses via PocketBase REST API.
